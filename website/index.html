Yours, and private

Local-first. Private by default.

Your library is a plain SQLite file on your own machine. No account, no cloud, no telemetry. SnipVault works fully offline — and nothing is ever sent anywhere unless you turn on sync.

  • You own the file. A single snippets.db you can back up, move, or open yourself.
  • Open source, MIT. Audit every line on GitHub — no black box.
  • Opt-in sync. Self-hosted only; there is no SnipVault cloud.
  • Secure by default. Signed auto-updates; sync token kept in your OS keychain.

Sync — on your terms

Your machines, in step. Without the cloud.

Run the tiny self-hosted server and your devices reconcile two-way, newest-edit-wins — new prompts, edits, and deletions all flow. Private per-user vaults, token auth, one command to stand it up.

  • Two-way incremental sync (offline-friendly)
  • Multi-user private vaults on one server
  • Docker, or bare Node — you choose

FAQ

Good questions

Is it free?

Yes — SnipVault is open source under the MIT license. No paid tiers, no upsell.

Where is my data stored?

In a local SQLite file on your machine. Nothing leaves your device unless you set up your own sync server.

Do I need an account?

No. There's no sign-up and no SnipVault cloud.

How does syncing work?

You run a small self-hosted server (Docker or Node). Devices sync two-way and the most recent edit wins per prompt. It's optional.

Which platforms are supported?

Desktop apps for Windows and macOS (Apple Silicon & Intel). On Linux you can run the web app or build from source.

Is it only for AI prompts?

It's just as good for code snippets — mark each entry's kind; the token estimate hides for code.

Can I import my existing prompts?

Yes — JSON, .md, and .txt, including drag-and-drop and multi-file import.
